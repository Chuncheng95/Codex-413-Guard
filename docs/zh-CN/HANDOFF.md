# 预警与 HANDOFF 指南

## 先理解预警的边界

`session_health.py` 查看的是本机 rollout 文件，不是网络抓包。请求体可能被 Codex
重新组织、压缩、裁剪或加入其他字段，因此脚本只能做趋势提醒，不能宣布“还剩多少
MB 一定会报错”。服务商和中间代理也可能随时调整限制。

默认规则：

- 低风险：小于 20 MB；
- 提醒：20–35 MB；
- 高风险：35 MB 及以上。

这套线来自一次约 50 MB 附近发生 413 的个案所采用的保守余量，不是平台规格。
如果你知道自己的入口限制，请用 `--warn-mb` 和 `--critical-mb` 修改。

## 什么时候交接

不要只等红线。以下任一时机都适合写 HANDOFF：

- 一个阶段刚完成；
- 即将收工、换方向或换模型；
- 视觉工具已经产生很多截图；
- 体检进入 warning 或 high；
- 下一步操作风险高，之后需要清楚回滚。

## 一条命令取得提示词

```bash
python3 scripts/session_health.py --handoff-prompt zh
```

提示词会要求当前 Agent 把状态写进 `.codex-handoff/HANDOFF.md`，内容包括目标、
证据、改动、卡点、下一步、踩坑和素材位置。

## HANDOFF 模板

```markdown
# HANDOFF

## 1. 当前目标

## 2. 已确认事实与证据

## 3. 已改动文件

## 4. 未完成事项与卡点

## 5. 下一步可执行动作

## 6. 关键上下文与踩坑

## 7. 相关素材位置
```

只写接手者真正需要的信息。不要复制：

- API 密钥、令牌或配置文件原文；
- 完整会话 UUID；
- 含用户名的绝对路径（可改为仓库相对路径）；
- 真实日志全文；
- 私人图片内容或 base64。

## 新会话如何接手

新会话第一句话可以写：

```text
请读取 .codex-handoff/HANDOFF.md。先复述当前目标、已完成内容和下一步第 1 项；
指出仍需我确认的地方，然后再继续。不要重新生成已有产物。
```

确认新会话接手后，旧会话继续保留作只读参考。

## AGENTS.md 不是后台监控

把规则放进 `AGENTS.md` 可以提醒 Agent 在阶段节点主动运行体检和写 HANDOFF，但它：

- 不会常驻后台；
- 不会每轮自动收到 rollout 文件大小；
- 不一定能可靠映射当前聊天和具体 rollout；
- 不应在没有脚本结果时声称“已到 70%”。

需要按小时检查时，请用户显式配置自己的系统调度器或 Codex Automation，并让通知只在
风险等级变化或需要行动时出现。
